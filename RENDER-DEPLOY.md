# Deploy Parallax on Render

Render gives you managed Postgres + a web service (the API) + static hosting
(the web SPA) in one account, with GitHub auto-deploy. This matches the
`docker-compose.yml` setup you already have.

## What gets deployed

| Piece     | Render type      | Source                  | Notes                                  |
|-----------|------------------|-------------------------|----------------------------------------|
| Postgres  | Postgres service | managed by Render       | `ensureSchema()` creates tables on boot|
| API       | Web service      | `apps/api` (Dockerfile) | `node apps/api/dist/index.js` on :4000|
| Web       | Static site      | `apps/web/dist`         | built with `VITE_API_URL` at build time|

No migrations to run by hand — the API creates its own tables on startup.

## Steps

1. **Push the repo to GitHub** (already done: `origin/main`).

2. **Create a Render account** at https://render.com and connect your GitHub.

3. **New → Blueprint**. Select the `parallax` repo. Render reads `render.yaml`
   and proposes the three services. (If you prefer the free tier, edit
   `render.yaml` first — see the commented block at the bottom — to use the
   Node runtime instead of Docker for the API.)

4. **Set the secrets Render can't generate:**
   - `AI_API_KEY` (and optionally `OPENAI_API_KEY`) — paste your real keys in
     the API service's Environment tab. Without `AI_API_KEY`, the API boots
     fine but `/ai` calls return 503 (login/register never need it).
   - `JWT_SECRET` is auto-generated by Render (`generateValue: true`); you can
     leave it.

5. **Deploy.** Render will, in order:
   - provision Postgres,
   - build + start the API (it connects to Postgres and runs `ensureSchema()`),
   - build the web SPA and publish `apps/web/dist`.

6. **Verify:**
   - API liveness: `https://parallax-api.onrender.com/healthz` → `{"status":"ok"}`
   - API readiness: `https://parallax-api.onrender.com/readyz` → `{"status":"ready"}`
     (only 200 once Postgres is reachable)
   - Web: open `https://parallax-web.onrender.com`, register an account, log in.

## Important: production fail-fast

The API runs in `NODE_ENV=production` on Render. Our M6 hardening means it
**refuses to start** if:
- `DATABASE_URL` is a localhost/default value (Render's managed Postgres is a
  real remote URL, so this is satisfied),
- `WEB_ORIGIN` is localhost (Render sets it to the real web URL via `fromService`),
- `AI_API_KEY` is empty (this only *warns* in production, it does not block boot).

If the API fails to start, check the deploy logs — the structured error tells
you exactly which check failed.

## Free-tier vs paid

- **Free plan:** use the Node-runtime API block in `render.yaml` (commented out).
  Free Postgres sleeps after 15 min of inactivity; the first request after that
  is slow while it wakes.
- **Starter ($7/mo):** keep the Docker runtime as written. Always-on, faster
  cold starts, and closer to your `docker-compose` local setup.

## After deploy

- Rotating `JWT_SECRET`: regenerate it in the Environment tab; existing tokens
  invalidate (users re-login).
- Custom domain: add it in the web service's Settings; update `WEB_ORIGIN` to
  match so CORS stays happy.
- CI already runs `typecheck + build + tests` on push via `.github/workflows/ci.yml`.
